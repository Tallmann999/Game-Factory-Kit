# Работа с Game Factory Kit

Это исходники переносимого набора навыков, а не текущая игра. Просьба настроить набор и цитирование стартовой фразы не запускают интервью. Не запускай прототип ради изменения документации набора.

В этом проекте и его чате разрабатываются сам набор, скиллы, конструктор, запуск автоматических задач и управление их чатами. Приложенные отчёты, снимки экрана и пути чужого игрового проекта используются как материал диагностики инструмента; они не выбирают игру для подключения и не поручают продолжать её задачи. Для проверок используй отдельные временные проекты. Реальную игру подключай только по явному поручению пользователя для этой игры; её документы, карточки и исследования веди в её собственной папке и чате.

При просмотре конструктора в рамках разработки набора открывай автономный `docs/pipeline/index.html` (при необходимости через локальный статический сервер этой папки). Проектный сервер `scripts/project.cjs` предназначен для работы в явно выбранной игре. Не переключай этот чат на ранее использованную тестовую игру.

Для реального старта «Хочу сделать игру» или «я хочу создать игру» используй `skills/game-creator/SKILL.md`. Прочитай его по относительному пути, если навык ещё не установлен. При продолжении игры сначала восстанови её состояние. Не меняй глобальный AGENTS.md/config автоматически.

По запросу «покажи конструктор» используй проектный режим из `skills/game-creator/references/project-dashboard.md`. Если клон вложен в игру, передавай корень игры. Если известна только папка набора, уточни папку игры. После записи первой идеи открой схему и передай ссылку в тот же чат.

README и пользовательские инструкции веди кратко на русском. Вход новой версии — `$game-creator`; старый `$game-factory-kit` относится к предыдущей версии в истории Git.

Правки навыков проверяй `python scripts/kit.py validate`. Правки CLI проверяй `python -m unittest discover -s tests -v`. Перед релизной упаковкой сверяй docs/VALIDATION.md и лицензии. Исходную коллекцию пользователя за пределами этого репозитория сохраняй.

Заметные изменения фиксируй в CHANGELOG.md. Не утверждай, что редактор, игровая механика или платформа проверены, если выполнена только проверка набора.
