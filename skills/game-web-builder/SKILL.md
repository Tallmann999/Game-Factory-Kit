# Программист Web MVP

Прочитай концепт, P0, технический план и существующий package.json/lockfile. Для новой простой механики достаточно HTML/CSS/JS Canvas; для 2D со сценами, спрайтами и столкновениями обычно подходит Phaser; для 3D — Three.js. React/R3F выбирай, если это нужно существующему React-приложению. Не ставь движок и сложный pipeline ради одной кнопки. Не мигрируй существующую major-версию автоматически.

Перед новым API/пакетом проверь официальный документ под выбранную версию. Закрепляй зависимости и lockfile; не полагайся на CDN `latest`. HTML означает браузерный результат, а не обязательство написать всю игру в одном файле. Для модулей и загрузки ассетов используй локальный HTTP-сервер; file:// часто недостаточно. Сначала используй существующие команды проекта.

## Реализация среза

1. Свяжи текущий F-ID с одним наблюдаемым действием. Создай цикл ввода → симуляция → обратная связь → результат, затем restart. Не оставляй меню единственным работающим экраном.
2. Отдели состояние раунда от рендера и HUD. Пусть restart снимает таймеры/обработчики, очищает объекты и возвращает исходное состояние. Обрабатывай blur/pause, чтобы зажатые клавиши и прошедшее в фоне время не ломали игру.
3. Используй dt с разумным ограничением или fixed step там, где важна стабильная симуляция. Не привязывай скорость к FPS. Не смешивай системы физики без необходимости. Проверяй координаты указателя после resize, камеру и масштаб canvas.
4. Нацеливай управление на выбранное устройство. Тач требует своего теста; суженный desktop viewport не подтверждает touch. UI не должен перехватывать игровой ввод вне своих областей.
5. Дай осмысленные loading/error состояния для внешних ресурсов. Ассеты сначала могут быть простыми геометрическими заглушками, если это позволяет проверить гипотезу. Подключай `game-art-director`, `game-ui-design`, `game-audio` по потребности.
6. Проверь сборку/консоль и реальный раунд через доступный браузер. Тестируй основные действия, проигрыш/победу и повтор. Сохрани команду запуска, URL/порт и результаты в QA/state. Если браузера нет, явно оставь gameplay not_run.

Для Phaser 4 предметные phaser-* дают детали сцен/ввода/анимаций/масштаба/DataManager/Arcade/Matter. Сначала проверь наличие профиля и фактическую версию. Для Phaser 3 обращайся к соответствующей официальной документации. Для 3D разделяй visual mesh и collision shape, проверь свет, near/far, aspect и загрузку GLB; производительность оценивай на целевом устройстве.

Официальные точки входа: [Phaser](https://docs.phaser.io/), [Three.js](https://threejs.org/docs/), [MDN Canvas](https://developer.mozilla.org/en-US/docs/Web/API/Canvas_API). Поиск текущих методов не заменяет чтение версии проекта.
