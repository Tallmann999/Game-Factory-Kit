# Игровой UI/UX

Начни с действий игрока и нужной информации, затем выбери UI. На первом экране должны быть понятны цель и начало игры; во время раунда — только нужные сигналы. Не закрывай основное игровое поле постоянными панелями. Отделяй настройки, справку и детали прогрессии от срочной информации.

Опиши состояния: start, loading/error при необходимости, active, pause, result, restart. У каждой интеракции должны быть доступный ввод, видимая реакция и понятный результат. Клавиатурный focus/return/escape и мышь/тач проверяй под целевое устройство. Уважай safe areas, читабельность текста, достаточные зоны касания, контраст и mute/reduced motion, когда они относятся к проекту.

Разделяй игровое состояние и UI-представление: монеты, таймер или здоровье не должны жить в нескольких несогласованных копиях. Меню корректно ставит игру на паузу, не оставляет pointer lock или удержанные клавиши. Для canvas проверяй преобразование координат после resize; DOM overlay не должен блокировать поле невидимыми областями. В Unity/Roblox используй принятый UI pipeline проекта и проверяй реальные viewport/device режимы.

Результат — рабочий интерфейс и короткие доказательства: первый экран, раунд, ошибка/результат, узкий экран и возврат в игру. Смотри скриншоты и взаимодействуй: одного DOM snapshot недостаточно. Для wireframe достаточно простого локального прототипа; Figma подключай при реальной потребности и доступном инструменте.
