# UI для Roblox

Применяй при работе с HUD, меню, уведомлениями и управлением Roblox-игры. Сначала прочитай документацию выбранных F-ID и существующую UI-спецификацию. Для фич без интерфейса этот модуль не нужен. Явные указания автора и договорённости конкретной игры учитывай прежде каталога; не переоформляй существующие экраны без задачи.

Три дополнительных модуля находятся рядом в `references/`:

| Задача | Модуль | Выход |
| --- | --- | --- |
| Правила сборки и проверки | [UI_GENERATION_GUIDE_DRAFT.md](references/UI_GENERATION_GUIDE_DRAFT.md), v0.10 | Карта экранов, рабочие пути, проверка UI-01–UI-11 |
| Выбор оформления | [UI_STYLES.md](references/UI_STYLES.md), каталог v0.9 | Зафиксированный ID/версия; доступен Toy Brick v0.8 |
| Спецификация фичи | [UI_SPEC_TEMPLATE.md](references/UI_SPEC_TEMPLATE.md), v0.6 | `docs/Features/<FeatureName>.UI.md` |

Перед проектированием/генерацией прочитай общую инструкцию. Каталог читай при выборе или применении стиля, шаблон — при подготовке спецификации. Для узкой правки уже описанного экрана читай соответствующие разделы и существующие ID, не заполняй весь шаблон заново. Названия «UI Aspect», «Place» или «GUI» сами по себе не означают наличие дополнительных файлов: комплект содержит эти три документа.

1. Найди источники состава, данных и действий UI. Не добавляй игровые правила, цены или поясняющий HelperText от себя. Стиль берётся из решения автора/спецификации. Если он ещё не выбран, спроси только о стиле и продолжай независимую инвентаризацию. Не назначай Toy Brick автоматически.
2. Для переносимых ссылок запусти `python <путь-к-этому-скиллу>/scripts/prepare_ui.py <корень-игры> --feature <FeatureName>`. Команда копирует три модуля в `Instructions/UI/` и создаёт черновик спецификации, сохраняя существующие файлы. Если найдены отличающиеся инструкции, сверяй их с авторскими правилами перед обновлением. Команда не подключается к Studio и не создаёт готовый интерфейс.
3. Заполни нужные разделы спецификации по F-ID: источники, UI/CMP/TOK/ACT/AST/DATA/TXT/SND, состояния, конкретная геометрия, отсутствующие ID и проверки. Для общей карты используй `Game.UI.md` при необходимости.
4. Когда поручена реализация, используй доступный Studio/MCP или исходники проекта через `game-roblox`. Сохраняй Scale, нулевые Offset и центральный AnchorPoint. Игровой код не перестраивает авторские Size/Position/CanvasSize. Не переносись на web UI-инструменты.
5. Новые объекты генерируй в ограниченные ветки `RojoGenerated`. Рабочие пути фиксируются отдельно. Автор вручную переносит объекты; до подтверждения переноса интеграция остаётся незавершённой. Только после подтверждения убери соответствующие генераторы/привязки Rojo, сохранив другие объекты. Для уже существующего UI правь выбранную рабочую ветку, не создавай дубликат всего интерфейса.
6. После изменения обнови `docs/Features/UI_HIERARCHY.md`: только фактическое дерево имён и классов. Проверь соответствующие UI-01–UI-11, ввод, очистку, границы и состояния. В отчёте различай исходники, Studio Play, симулятор и физическое устройство; недоступные проверки пометь `not_run`.

Изображения используются только по Roblox ID, выданным для этой игры; пример ID из каталога не является разрешением для новой игры. Отсутствующие Image/SoundId остаются пустыми с записью в спецификации. Не запускай генерацию или поиск картинок вместо запроса ID. Пустые звуковые ID не блокируют интерфейс. Обычные заливки, текст и обводки не требуют изображения.

В Toy Brick — белый текст с тёмной обводкой; внешняя и внутренняя обводки одной поверхности, фиксированная плитка 120×120 только для TileSize. Свойства UIStroke и прочие API проверяй по доступной версии Studio и официальному Creator Hub; не подменяй отсутствующее свойство молчаливым изменением стиля.

Тексты игры по комплекту — English; отчёты автору — на русском. Основное меню Roblox само по себе не останавливает время сервера. Тестовый UI имеет сворачивание и исключается из финального place. После принятой фичи действует общий порядок Feature Index, проверки контекста, коммита и push в выбранную автором ветку.
