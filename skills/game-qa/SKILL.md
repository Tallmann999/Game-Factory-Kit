# QA и плейтест

Возьми P0 acceptance из Feature Index и составь минимальную цепочку действий игрока. Для каждого случая запиши setup, шаги, ожидаемый и фактический результат, среду/build, evidence и `PASS/FAIL/NOT_RUN`. Начни с запуска → цели → основного действия → результата → restart; затем существенные границы, пауза/blur, resize и повторные действия. Не добавляй много тестов, копирующих реализацию.

Web проверяй доступным browser tool/Playwright/CUA, canvas/WebGL дополнительно скриншотами. Unity: compilation/Console, Play Mode и конкретная сцена; Roblox: Output, Play, device simulator и несколько клиентов для сетевой механики. Чтение C#/Luau не заменяет запуск. Если editor/браузер недоступен, выполни независимые проверки и честно укажи runtime blocker.

Ошибки: severity, эффект для игрока, воспроизведение, ожидаемое, наблюдаемое, evidence и вероятный владелец. Проверяй исправление повторением сценария; не повторяй весь набор без причины. Performance записывай как замер на указанном устройстве/сцене; средний FPS не скрывает провалы кадра. Для импортируемых ассетов проверяй настоящий результат, а не только наличие файла.

## Проверка гипотезы

Сформулируй: кому даём играть, какую неизвестность снимаем, какую задачу даём без подсказки и как изменится решение по результату. Для первого качественного теста полезна небольшая доступная выборка, но она не доказывает рыночный спрос и не даёт надёжного retention. Записывай размер/источник выборки, поведение, затруднения, прямые отзывы и ограничения; отделяй слова людей от интерпретаций. Не выдумывай игроков и их реакцию.

При отсутствии внешних тестировщиков подготовь сценарий и материалы, сохрани `human_test: not_run`. Итог: P0 реально проверенные, блокеры, гипотеза supported/unsupported/inconclusive с основаниями и следующий дешёвый тест. Обнови QA/state и статусы F-ID только по фактам.

## Визуальное покрытие

Для реальных кадров проверь переполнение текста, перекрытия, читаемость, масштаб и положение эффектов. При анимации — контакты и переходы с учётом стиля. Отсутствие инструментированных состояний, суставов, кадров или устройства означает NOT_RUN для этой проверки, даже если остальной smoke test прошёл. Сходство с референсом оценивай в согласованных пределах; оно не доказывает интерес игры.

При настройке механики запиши параметры до/после и наблюдения, предложи пользователю 3–5 действий для проверки. Исправляй крупнейший подтверждённый недостаток; пользовательский отзыв не подменяй выводом автоматического теста.
