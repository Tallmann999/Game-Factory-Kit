# Звук и музыка

Составь маленькую event map из core loop: действие, успех/ошибка, предупреждение, конец раунда, UI. Для каждого звука укажи назначение, приоритет, допустимую частоту, пространственный/непространственный режим и громкость относительно других. Музыка нужна, если поддерживает выбранный опыт; она не обязательна для проверки механики.

Проверь доступные средства: существующие assets, лицензированные библиотеки, генерация или процедурный звук через API движка. Не обещай аудиогенерацию без инструмента. Сохраняй source/license/attribution в asset-register; референс-трек не означает разрешение включать его в игру.

Web-аудио запускай после user gesture, обрабатывай suspended AudioContext и отказ autoplay. Дай mute/volume; избегай повторного запуска loops при restart. Ограничивай одновременные голоса и спам событий, делай вариации там, где частое повторение утомляет. В 3D проверь attenuation и связь listener/camera. Не оставляй критическую информацию только в звуке.

Проверяй фактическое воспроизведение, отсутствие clipping и дублей после pause/restart на целевых устройствах. Когда доступна только статическая проверка, пометь listening test not_run. Сохрани пути, события и параметры микса в техническом плане.
