# Конструктор в папке игры

Работай с корнем конкретной игры. Если открыт только клон набора и папка игры ещё неизвестна, уточни, где сохранить игру. Клон может лежать в подпапке игры или отдельно. При установке через `kit.py install --project` путь к клону записывается в `.game-factory/kit-location.txt` относительно корня игры либо как абсолютный путь на другом диске. Иначе найди в рабочей области клон с `kit.json` и `scripts/project.cjs`.

1. На первом старте сохрани полученную идею в существующем документе игры или в `docs/game/idea.md`. Пустые шаблоны оставляй незаполненными до разговора. По просьбе показать существующую игру сразу переходи к анализу.
2. Из каталога набора выполни `node scripts/project.cjs "<папка игры>" --audit`. Сверь проценты и оставшиеся критерии с документами, сценами и кодом проекта. Для существующей игры найди также документы с нестандартными названиями. Для выводов, которые требуют исполнения, используй соответствующий скилл и реальную проверку. Если проверки нет, укажи ближайшую проверку и оставь этап открытым. Для осознанного пропуска визуальной доски запиши решение автора.
3. Чтобы привязать доказательство и результат аудита к этапу, выполни `node scripts/project.cjs "<папка игры>" --record research 50 "design/market.md" "Сравнить управление у двух аналогов"`. Подставь проверяемую долю, ID этапа, реальный относительный путь и оставшийся шаг. Записывай результат после каждой принятой работы. Если нет материалов, оставь 0%. Сборка считается по принятым F-ID активного объёма. Большой проект можно анализировать по частям с честной отметкой покрытия.
4. Запусти `node scripts/project.cjs "<папка игры>"` как локальный сервер. Открой **точный адрес из stdout** в доступном браузере Codex или дай ссылку в этом чате. Пока сервер работает, конструктор освежает данные проекта. При продолжении открывай тот же проект. В карточке есть документы, условия завершения и статус. Поле задания исполнителю включает реальные входы и правила вопросов автора.
5. До первой реализации получи явный выбор ветки и remote. По каждой принятой фиче отправляй один коммит с F-ID, изменениями и обновлённым Feature Index. Ошибку проверки или push записывай в карточку. Для очереди читай [robocop.md](robocop.md).

## Передача в следующий чат

Перед границей контекста запиши в документы игры текущий F-ID, подтверждённый результат, последнее испытание, открытый вопрос и ближайшее действие. Получи актуальный промпт командой `node scripts/project.cjs "<папка игры>" --handoff` или кнопкой **В новый чат**. В интерактивном Codex используй доступную передачу чата в рамках разрешений пользователя; если её нет, дай пользователю промпт. Робокоп сам запускает свежую CLI-сессию в той же рабочей копии по сохранённой сводке. После перезапуска сверяй SHA, ветку, состояние push и карточку перед продолжением.
