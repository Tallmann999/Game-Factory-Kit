# Конструктор в папке игры

Когда автор просит начать создание игры по этапам через конструктор, запусти из клона `python scripts/kit.py start --project "<папка игры>"`. Можно указать `--profile roblox` для Roblox. Передай автору напечатанную ссылку. Она открывает карточку первого доступного этапа, включая незавершённый этап при продолжении. После сохранения результата кнопка **Открыть этап** ведёт к очередной доступной задаче.

Эта инструкция применяется при явной работе с выбранной игрой. При настройке самого Game Factory Kit используй автономный `docs/pipeline/index.html` из клона и временные проекты для проверок запуска. Отчёт или скриншот другой игры служит диагностике инструмента; упоминание её пути не является выбором проекта. Подключение реальной игры и продолжение её задач требуют отдельного явного поручения для этой игры и выполняются в её собственной папке и чате.

Работай с корнем конкретной игры. Если открыт только клон набора и папка игры ещё неизвестна, уточни, где сохранить игру. Клон может лежать в подпапке игры или отдельно. При установке через `kit.py install --project` путь к клону записывается в `.game-factory/kit-location.txt` относительно корня игры либо как абсолютный путь на другом диске. Иначе найди в рабочей области клон с `kit.json` и `scripts/project.cjs`.

1. На первом старте сохрани полученную идею в существующем документе игры или в `docs/game/idea.md`. Пустые шаблоны оставляй незаполненными до разговора. По просьбе показать существующую игру сразу переходи к анализу.
2. Из каталога набора выполни `node scripts/project.cjs "<папка игры>" --audit`. Сверь проценты и оставшиеся критерии с документами, сценами и кодом проекта. Для существующей игры найди также документы с нестандартными названиями. Для выводов, которые требуют исполнения, используй соответствующий скилл и реальную проверку. Если проверки нет, укажи ближайшую проверку и оставь этап открытым. В маршруте новой игры доска завершена после выбора одного из трёх показанных направлений.
3. Чтобы привязать доказательство и результат аудита к этапу, выполни `node scripts/project.cjs "<папка игры>" --record research 50 "design/market.md" "Сравнить управление у двух аналогов"`. Подставь проверяемую долю, ID этапа, реальный относительный путь и оставшийся шаг. Записывай результат после каждой принятой работы. Если нет материалов, оставь 0%. Сборка считается по принятым F-ID активного объёма. Большой проект можно анализировать по частям с честной отметкой покрытия.
4. Запусти `node scripts/project.cjs "<папка игры>"` как локальный сервер. На Windows автоматический исполнитель требует обычную учётную запись пользователя: используй `scripts/start-project.ps1 -Project "<папка игры>"` из обычного PowerShell или разрешённый запуск вне sandbox. Не меняй глобальные security settings и не убирай защитные переменные среды для обхода проверки. Проверь `/api/runtime`: пользователь, профиль, фактический путь/версия CLI и вход; открытие страницы не подтверждает выполнение задания. Открой **точный адрес из stdout** в доступном браузере Codex или дай ссылку в этом чате. Пока сервер работает, конструктор освежает данные проекта. При продолжении открывай тот же проект. В карточке есть документы, условия завершения и статус. Поле задания исполнителю включает реальные входы и правила вопросов автора.
5. До первой реализации получи явный выбор ветки и remote. По каждой принятой фиче отправляй один коммит с F-ID, изменениями и обновлённым Feature Index. Ошибку проверки или push записывай в карточку. Для очереди читай [robocop.md](robocop.md).

После ответа автора из чата можно сохранить решение командой из клона: `node scripts/project.cjs "<игра>" --platform "Unity" "Компьютер" "3D"` либо `node scripts/project.cjs "<игра>" --mode manual` (для очереди — `robocop`). Подставь выбор автора. Эти команды проверяют завершение предыдущих этапов так же, как конструктор. Остальные решения автор принимает в чате, скилл записывает их в docs/game/state.json и документы этапа.

Для обзора уже существующей игры открой **Аудит проекта** и запусти `$game-project-audit`. Он проверит все этапы, в том числе по документам с нестандартными именами, и привяжет к карточкам источники и оставшуюся работу. Для одного задания заполни **Следующий шаг**. **Работать в чате Codex** открывает чат в папке игры с подготовленным сообщением. Автор отправляет его и видит работу в этом же чате. **Запустить автоматически** проверяет среду и запускает фоновую работу. ID/ссылка чата доступны после первого события; ход виден в карточке и ограниченном очищенном журнале. Раннее открытие CLI-чата может показать неполную историю, поэтому автоматическое открытие сохранено после записи ответа. При отсутствии событий карточка показывает застой; кнопка остановки завершает только проверенное дерево этого задания, после чего разрешён повтор или ручной чат. Ошибка открытия окна не меняет результат задания. Если браузер блокирует codex://, автор может скопировать подготовленный текст в новый чат игры. В обоих случаях укажи выводы и ссылки на итоговые документы в чате, передай статус и прогресс карточке.

## Передача в следующий чат

Перед каждой фичей и при приближении к границе контекста выполняй [правило проверки и передачи](context-handoff.md). Получи исходную сводку командой `node scripts/project.cjs "<папка игры>" --handoff` и дополни её проверенными изменениями текущей работы. Назови продолжение по F-ID и названию из Feature Index. Для запущенного из карточки чата передай владельца через `stage-chat.cjs handoff`, затем отправь сводку в продолжение. Дождись подтверждения начала. После перехода сверяй SHA, ветку, состояние push и карточку перед продолжением.
