# Плейтест и визуальная проверка по этапам

## Настройка механики

1. Выбери один наблюдаемый результат и одну неизвестность: например, игрок понимает момент уклонения.
2. Для рискованного движения/боя/физики сделай небольшую тестовую сцену и доступные параметры. Для простой правки достаточно текущей игры.
3. Добавь минимальную обратную связь, проверь сценарий сам и посмотри реальный кадр.
4. Дай пользователю 3–5 действий, включая ошибку/проигрыш и повтор, когда применимо. Спроси, что понятно, интересно и что мешает.
5. В qa.md запиши сцену/build, параметры до/после, наблюдения и дословный отзыв. Решения отрази в концепте, задачи — в Feature Index, следующий шаг — в state.json.
6. Исправь крупнейшую подтверждённую проблему и повтори затронутую проверку. Агентский прогон не означает пользовательского одобрения.

Сначала докажи start → действие → исход → restart. Если цикл неинтересен, меняй его до расширения контента. Регрессионные тесты нужны для воспроизводимых ошибок, а не каждой субъективной оценки.

## Браузерная игра по изображению

До реализации — компактная доска; затем игровой цикл с временной графикой. Сохраняй существующий Canvas/Phaser/Three.js/R3F стек. Для нового проекта выбирай подходящую доступную основу; этот набор не поставляет движок ref2game.

После первого плейтеста выбери один экран целевого качества. Перечисли необходимые ассеты, сохраняй источники и условия использования в asset-register. Генерируй/подготавливай части доступными инструментами и постепенно подключай в работающий preview. Держи согласованными масштаб, anchor, слои и collision footprint. Заранее уточни, нужно вдохновение или близкое сходство, если это существенно меняет объём.

## Проверки и доказательства

- Runtime: запуск, загрузка ресурсов, консоль, ввод, исход и повтор.
- Интерфейс/кадр: переполнение текста, перекрытия, читаемость, масштаб, слои, положение эффектов.
- Движение при наличии: контакт стоп, скачки суставов/состояний и момент действия. Пороги учитывают стиль; намеренная хромота не считается ошибкой автоматически.
- Художественное направление: сравнение фактического кадра и выбранного референса. Численный балл — дополнительный сигнал, не доказательство интереса игры.

Различай выполненные автоматические проверки, визуальные наблюдения и NOT_RUN. Если нет захвата, тестовых состояний, суставов или доступа к устройству, соответствующая проверка не выполнена. Не объявляй универсальный qa.mjs подключённым. Production build проверяется отдельно от dev preview; дальнейшую полировку ограничивай текущим этапом.
