# Ассет-пайплайн

Определи целевую платформу, камеру, важность ассета на экране и измеряемый бюджет. Треугольники, материалы, размеры текстур, кости и длины клипов зависят от конкретной сцены/устройства; фиксированные универсальные лимиты не заменяют замер. Прежде чем моделировать, проверь, нельзя ли проверить механику простой заглушкой.

Сохраняй исходник (например .blend), промежуточные экспорты и runtime output в понятных отдельных местах. Asset register содержит происхождение, лицензию, атрибуцию и путь. Для чужих Roblox моделей проверь доступность MeshId/TextureId/AnimationId и права целевого владельца; локальный файл не гарантирует право использовать зависимости.

Для Blender начни с `blender-core` и фактической версии. Моделирование/UV/PBR/rig/animation подключай по задаче. Геометрию заверши числовой и визуальной проверкой через `blender-asset-qa`; допускай осмысленные открытые поверхности для игровых плоскостей и документируй принятое исключение, не заполняй меш лишь ради формального watertight. Экспорт выполняй на копии, сохраняй исходный rig/модификаторы.

Проверь масштаб, оси, pivot, нормали, UV, материалы и цветовые пространства, текстуры, skin weights и анимационные клипы. Для game rigs проверь сильные позы и loop seam. Целевой движок должен действительно импортировать результат: открой файл, проверь dimensions, материал, движение, collision и доступность ресурсов. GLB обычно удобен для Web; Unity/Roblox формат выбирается под задачу и актуальные importer docs.

Оптимизируй по измеренному bottleneck: draw calls/materials, текстурная память, геометрия/LOD, skinning или overdraw. Сравнивай before/after на одной сцене. Отчёт содержит файлы, размеры, tris/materials/textures, проверенную программу и оставшиеся ограничения; успешный export operator сам по себе не подтверждает корректный runtime.
