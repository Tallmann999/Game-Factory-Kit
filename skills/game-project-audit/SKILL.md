# Аудит игровой папки

Прочитай инструкции игры, её активную схему и канонические документы. В конструкторе кнопка **Аудит проекта** запускает тебя для всей игры. При вызове из чата получи исходные данные через `node scripts/project.cjs "<игра>" --audit` из клона набора. Путь к клону хранится в `.game-factory/kit-location.txt`.

Сопоставь каждый ID этапа и его критерий с содержанием имеющихся файлов независимо от их имени, даты и скилла, с которым их создавали. Ищи в GDD, журналах решений, спецификациях, Feature Index, исходниках, сценах, истории изменений и сохранённых отчётах тестов. Исключи кэш движка и зависимости. Для каждого зачтённого критерия дай путь и короткий факт с разделом, сценой или F-ID, по которому автор сможет проверить вывод. Отдельно укажи остаток и ограничения осмотра.

- Поле «Следующий шаг» и пустой шаблон показывают намерение. Начисляй процент за выполненные критерии. Ноль означает, что подтверждения не найдены в осмотренных материалах. Промежуточный процент объясни долей критериев.
- Для исследования проверь три вещи: содержательное сравнение похожих игр, проверяемые источники об этих играх, гипотезу с наблюдаемым критерием. Гипотеза может уже быть в GDD или плане плейтеста. Художественные референсы оцени в этапе визуального направления. При аудите используй существующие результаты. Само исследование запускается из его карточки.
- В пошаговом маршруте проверь номер исследованной версии идеи и решение автора, утверждение полного концепта, три визуальных направления и выбор, согласованный объём MVP и рабочие F-ID. Сохранённые ответы и решения учитывай из документов. Процент аудита сам по себе не разрешает следующий этап.
- Для сборки используй принятые F-ID согласованного объёма. Для QA различай наличие теста, сохранённый результат прогона и ручную приёмку. В выборе платформы и режима учитывай зафиксированные решения автора. Недостающие решения оставляй открытыми.

Верни оценку по всем этапам схемы. Из кнопки конструктор принимает структурированный результат и сохраняет его сам. Из чата можно передать вывод командой `node scripts/project.cjs "<игра>" --import-audit "<отчёт.json>"`. Формат задан в `scripts/audit-result.json`: summary и stages с id, percent, remaining и evidence (path, fact). Сохраняй относительные пути внутри игры. Задания автора, игровые документы и код при обзорном аудите сохраняют своё назначение; предложения по переработке запиши в выводах.
