# Архитектура Game Factory Kit 0.2

## Что поставляется

Один Git-репозиторий с библиотекой 45 skill-папок, профилями в kit.json, шаблонами документов и CLI без внешних Python-зависимостей. `game-creator` является входом, а не копией содержимого остальных навыков. Специалист получает известные решения и конкретный результат. Ведущий процесс сводит принятые решения и не загружает все инструкции одновременно.

Python-CLI отвечает только за перенос файлов, проверку структуры и упаковку. Разговор, исследование, дизайн, программирование и работа с редакторами выполняются Codex и фактически доступными инструментами. Отдельный непрозрачный агентный runtime или сервис с API-ключами для текущей версии не нужен.

## Контракт проекта

Существующая структура документации имеет приоритет. Для пустого проекта используются восемь шаблонов `docs/game/`. Каждый этап оставляет минимальные входы следующему:

| Этап | Передаваемые сведения |
|---|---|
| Idea | Слова пользователя, player fantasy, действие, неизвестные |
| Research | Реальные аналоги/референсы, факты/URL/дата, ограничения, тестовая гипотеза |
| Concept | Петля, выбор/риск, обратная связь, успех/ошибка, отличие, исключения |
| Scope | F-ID, P0/P1/later, acceptance, зависимости, hypothesis test |
| Build | Версии, команды, конкретные изменения, assets, доступность runtime |
| Playtest | Действия, ожидаемое/фактическое, evidence, PASS/FAIL/NOT_RUN |
| Decide | Наблюдения и решение продолжить/уточнить/остановить |
| Port | Исходный build, целевая среда, mapping и проверка паритета |

`state.json` — краткий указатель, а не замена концепта и QA. Нулевые/unknown значения не заполняются домыслами. Содержимое документов не обязано проходить формальный JSON schema validation: CLI проверяет структуру набора, а не истинность игровых решений. Результаты проверок обновляет агент по фактам.

## Подключения

- Без сети: интервью, концепт, scope, локальная разработка с доступными зависимостями. Исследование рынка остаётся pending, если нет предоставленных источников.
- Web: Node/npm при использовании bundler/движка, либо простой браузерный путь. QA требует доступного браузера.
- Арт: простые локальные ассеты или доступный imagegen/редактор. API/платная генерация в пакет не входят.
- Blender: приложение и совместимая версия API. Включён upstream 5.2+, наличие файла SKILL не доказывает установленную программу.
- Unity/Roblox: реальный Editor/Studio и соответствующее живое подключение. Исходники, открытая сцена и сохранённый place/build — разные результаты.
- Маркетинговые базы: публичные данные достаточны для первого прохода; платные кабинеты/выгрузки включаются под конкретную гипотезу.

Профиль устанавливает инструкции, не программы. Doctor выдаёт PATH availability, а живой агент отдельно проверяет MCP. Названия инструментов определяются текущим хостом; нельзя зашивать в переносимый навык ID соединения из одной машины.

## Дальнейшее развитие

1. Первый реальный пользовательский прогон: от незнакомой идеи до Web build и честного playtest report. По результатам исправить узкие проблемы маршрутизации, не добавляя универсальную анкету.
2. При повторяемой нужде — отдельные Web templates/fixtures, к которым привязаны реальные проверки. В текущей версии не поставляется одинаковая демоигра под видом генератора всех жанров.
3. После проверки прав — опциональный пакет RobloxGameKit с явными версиями/ready modules и переносимыми путями. Новые upstream обновлять вручную, с review diff и сохранением notices.
4. При спросе — адаптация выбранных OGD-процедур с CC BY атрибуцией и ограниченным trigger. Не подключать всю методологию ко всякому вопросу.
5. При необходимости общего распространения — проверить плагин в поддерживаемой среде, затем публиковать. Существующий plugin.json — начальный manifest; каталог/серверная инфраструктура и публикация не проверены.

Уже проверенный Web MVP не заменяет отдельный vertical slice для Unity/Roblox/mobile. У будущей аналитики должны быть реальные данные, схема событий и сопоставимые определения метрик.

## Референсы и ранняя проверка

Перед новым build внутри текущих фаз показывается одна компактная доска. Выбор/делегирование/пропуск сохраняется в концепте, источники — в исследовании, указатель — в state.json. Новая обязательная фаза или файл схемы состояния не добавляются. Текущие проекты не требуют миграции.

game-creator содержит Python-помощник доски и схематический пример в assets/reference-board; они переносятся вместе с профилем и входят в ZIP. Он не запускает сервер, не скачивает референсы и не устанавливает пакеты. Инвентаризация окружения остаётся задачей существующего kit.py doctor, а рабочие подключения проверяет Codex. Нужные роли фиксируются в technical-plan.

Подходы к доскам, тестовым сценам и измерению движения вдохновлены studioigor/studioigor-skill, studioigor/3d-animator-skill и studioigor/ref2game. Их код и зависимости сюда не скопированы. Визуальные проверки выполняются доступными средствами; полный специализированный runtime не заявляется.
