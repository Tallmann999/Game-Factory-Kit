# Аудит локального набора скиллов

Дата: 26 октября 2026. Источник: `~/.codex/skills`.

Папка исследована без изменений исходных файлов и без запуска её установщиков, Blender-скриптов, Rojo или игровых проектов. Это статический аудит инструкций, состава ресурсов, путей, происхождения и повторов; он не подтверждает работоспособность всех примеров API на конкретной машине.

## Вывод

Набор уже хорошо закрывает программирование браузерных игр, Blender, Roblox и управление Unity через MCP. Главный пробел — единый короткий процесс от идеи через проверяемое исследование рынка к небольшому MVP. Также отсутствуют отдельные рабочие роли продуктового маркетинга, аудио, проверки мобильного релиза и планирования переноса между платформами.

Для нового инструмента нужен компактный главный скилл и дополнительные роли, которые подключаются по задаче. Загружать все 53 инструкции в каждый проект нецелесообразно. Установленные папки полезно сохранить как библиотеку специализаций, а распространяемый Git-пакет собирать с учётом происхождения и лицензий каждого компонента.

## Что уже работает как архитектурная основа

- `game-studio`, `web-game-foundations`, `phaser-2d-game`, `three-webgl-game` и `react-three-fiber-game` дают понятное разделение 2D, обычного Three.js и React-сцен.
- `game-ui-frontend` защищает игровое поле от перегруженного HUD, а `game-playtest` требует проверки реального поведения и скриншотов canvas/WebGL.
- `project-handoff` различает реализацию, сохранение и проверку, а также сохраняет состояние для продолжения в другом чате.
- `blender-core` ведёт к нужной специализации; `blender-asset-qa` содержит численные проверки геометрии, UV, нормалей, масштаба и весов. Это полезнее одного общего скилла «3D-моделлер».
- Roblox-обёртки различают сохранённый файл, исходники на диске и текущую сессию Studio. Это нужно сохранить в переносимом процессе.
- Unity-инструкция прямо предупреждает, что её API-примеры — шаблоны, которые необходимо сверять с установленной версией и текущим MCP.

## Пересечения и проблемы переноса

### Три конкурирующих входа

`game-project-start` требует старую фразу «я начинаю делать игру» и десять фиксированных тем до продолжения. `game-dev-toolkit` направляет в него. `game-studio` считает себя главным входом для браузерных игр и по умолчанию выбирает Phaser 2D. Эти инструкции по отдельности разумны, но вместе могут вызвать повторное интервью и преждевременный выбор стека.

Новый верхний вход должен распознавать «я хочу создать игру», первым выяснять идею и использовать уже известные ответы. Десять тем старого старта можно сохранить как внутренний список полноты, без обязательного предъявления десяти вопросов сразу. Существующие проекты нужно продолжать по состоянию, а обсуждение самого инструмента не должно запускать игру.

`gd-doc-kickoff` уже содержит ideation, concept и feature-index, однако ориентирован на подробную спецификацию: readiness-check, три направления, выбор направления, декомпозицию, выбор фичи и пакеты из 3–7 вопросов с минимум двумя вопросами «почему». Для короткого MVP его лучше применять к сложной выбранной фиче. Компактный концепт и первый индекс следует делать без обязательного повторения этого полного интервью.

### Абсолютные пользовательские пути

| Файл | Найденная привязка | Исправление в распространяемой копии |
| --- | --- | --- |
| `gd-roblox-kickoff/SKILL.md`, строка 8 | `~/.codex/skills/roblox-game-kit/assets/kit` | Вычислять соседний `roblox-game-kit/assets/kit` от папки скилла |
| `roblox-mvp-builder/SKILL.md`, строка 8 | Такой же абсолютный путь | Аналогично; отсутствие kit обозначать как недоступную зависимость |
| `sprite-pipeline/SKILL.md`, строки 61, 72, 84 | Три Python-команды с `~/.codex/skills/...` | Использовать путь к фактической папке скилла |

`playwright` использует bash, `export`, `command -v` и `.sh`-обёртку. Для Windows PowerShell нужен соответствующий запуск либо уже доступная браузерная автоматизация. Скилл не должен требовать ручной глобальной установки CLI, если поддерживаемый браузер уже предоставлен средой.

В `blender-core/scripts/run_in_blender.py` стандартные пути Windows, macOS и Linux являются путями обнаружения приложений, а не привязкой к одному пользователю. Это переносимый подход; есть также `BLENDER_EXE` и поиск по `PATH`.

### Старые подтверждения и версии

Каталог содержит утверждения «проверено Blender 5.2.2» и «инструменты Roblox Studio MCP доступны в чате». Это данные предыдущей сессии; на другом компьютере они не подтверждают ничего. Переносимый doctor должен обнаруживать приложения, версии и живое подключение заново.

Все 22 Blender-инструкции ориентированы на Blender 5.2+, а семь предметных Phaser-скиллов — на Phaser 4. Их нельзя применять к Blender 4.x или Phaser 3 без проверки. Установленная инструкция не является причиной миграции существующего проекта. Аналогично нельзя обещать Unity Play Mode или Roblox Studio Play по наличию текстового файла скилла.

### Файловые дубли

В девяти Web Game Studio папках повторяются одинаковые 16 файлов `references/` и три Python-скрипта. Каждая папка содержит 21 файл: собственные `SKILL.md` и `agents/openai.yaml`, плюс 19 общих ресурсов. В 20 Blender-папках находится одинаковый `_bpyx.py` размером 4503 байта.

Дубли не являются дефектом сами по себе: отдельный скилл может устанавливаться самостоятельно. При упаковке профилями можно оставить такую автономность. При поддержке своей единой библиотеки общие ресурсы лучше хранить один раз, но только после обновления всех ссылок и проверки независимой установки. Удалять повторы вслепую нельзя.

### RobloxGameKit: реализация и планы

`roblox-game-kit/assets/kit/module-catalog.json` содержит 17 модулей. Только пять имеют статус `ready`: `core`, `network`, `tags`, `economy`, `player-data`. Остальные 12 — `blueprint`, в том числе `analytics`, `monetization`, `ui` и `audio`. Их нельзя рекламировать как готовые инструменты аналитики, монетизации, UI и звука.

Локальный kit содержит собственный установщик скиллов и bootstrap. Переносимый пак не должен запускать вложенные установщики автоматически при знакомстве с идеей. Для существующего проекта следует интегрировать выбранные модули по его workflow; bootstrap предназначен для новой папки или изолированной staging-папки.

## Чего добавить в универсальный инструмент

| Роль | Нужный практический результат |
| --- | --- |
| Исследователь рынка и референсов | Сравнимые игры с URL, датой проверки, наблюдаемыми фактами, отличиями и ограничениями данных; отдельно Steam, web, mobile и Roblox |
| Концепт и ограничение MVP | Обещание игроку, центральный цикл, границы первого результата, индекс с MVP/P1/P2 и проверяемыми критериями |
| Маркетинг | Проверяемые гипотезы аудитории, позиционирование, тест сообщения, материалы для страницы и план проверки интереса; никаких придуманных продаж и выручки |
| Арт-директор | Короткое визуальное направление, список нужных ассетов и технические бюджеты; затем ImageGen/спрайты/Blender по доступности |
| Аудио | События звука, минимальный набор эффектов, уровни громкости, происхождение и условия файлов |
| Аналитика игрового теста | Вопрос теста, наблюдаемые события, выборка, результаты и решение по следующей итерации; без обещаний удержания по одному тесту |
| Перенос между платформами | Что переносится как дизайн/данные/ассеты, что реализуется заново; управление, серверная модель, UI, производительность и экономика |
| Мобильная проверка | Тач, разрешения/ориентация, бюджет устройства, offline/сохранения, реальные SDK и сборка по выбранному движку |
| Doctor зависимостей | Наличие CLI/движка, версия, доступная сессия MCP и непроверенные компоненты; инструкции сами программы не устанавливают |

Первый публичный вариант разумно делать на HTML: 2D — Phaser, 3D — Three.js; Unity и Roblox подключать профилями. Steam является площадкой распространения, mobile — семейством устройств, 2D/3D — способом представления, а premium/F2P — моделью распространения: интервью и состояние проекта должны хранить эти ответы отдельно.

Браузерный MVP может проверить игровой цикл, но не автоматически доказывает мобильную экономику, сетевое поведение Roblox или готовность Steam-релиза. Для каждой следующей платформы нужны свои проверки и соответствующая реализация.
