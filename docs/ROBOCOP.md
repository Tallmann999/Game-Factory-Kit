# Робокоп

Один F-ID — одна карточка, рабочая копия Git и отдельный коммит в выбранной удалённой ветке. Робокоп принимает индекс фич из Game Factory Kit и запускает Codex CLI по одной готовой фиче. Для хранения карточек достаточно диска на вашем компьютере.

## Подготовить игру

1. Запишите идею или передайте готовый концепт. После исследования аналогов автор описывает основные механики, пиллары и решает, какой концепт реализовать.
2. Утвердите таблицу в `docs/game/feature-index.md`. Доска читает штатный шаблон и таблицы с именованными колонками ID, название, приоритет, статус, зависимости и критерий готовности. Для автоочереди нужны стабильные ID вида F-001, приоритет P0/P1/later, зависимости через запятую и проверяемый результат. Робокоп берёт P0 перед P1 среди доступных задач. Строки later и cut остаются за пределами очереди.
3. Сохраните концепт, индекс, инструкции, необходимые ассеты и проектные проверки в Git игры. Исполнитель видит файлы из коммита. Нужны исходный коммит, настроенный автор Git, существующая локальная ветка и remote с доступом на push. Переключите рабочую папку на выбранную ветку. Установите Node.js 20+, Git и авторизованный Codex CLI.
4. В конструкторе выберите платформу, устройство, 2D/3D и откройте **Режим работы**. В **Ветка для фич** явно укажите ветку и remote. Используйте `.game-factory/pipeline.json` игры или скачайте JSON. Переключение режима само по себе сохраняет только выбор.
5. Откройте терминал в папке Game Factory Kit и запустите отдельную доску игры. После `--check` укажите **вашу команду приёмки**, которую можно выполнять в отдельной рабочей копии. Пример для проекта с тестом Node:

```powershell
node scripts/robocop.cjs "D:\Games\MyGame\game-pipeline.json" --project "D:\Games\MyGame" --check node --test tests/game.test.cjs
```

Откройте напечатанный адрес на 127.0.0.1. Команда проверки запускается напрямую с аргументами. Для составной проверки используйте скрипт проекта. Проверка должна возвращать ненулевой код при ошибке. Визуальную приёмку и плейтест задавайте отдельно в критериях фичи.

## Работа с карточкой

- **Ручной.** Доска рекомендует первую доступную фичу. Выберите любую доступную карточку, уточните Markdown-бриф и нажмите «Выполнить эту фичу». Проверьте результат в указанной рабочей копии. Примите коммит для отправки в выбранную ветку или запишите замечание в карточке.
- **Робокоп.** Нажмите «Запустить очередь». Пока терминал открыт и компьютер работает, диспетчер обрабатывает доступные фичи до восьми часов за запуск. Можно остановить очередь после текущей фичи. Исполнитель возвращает результат, запрос решения, запрос ревью или сводку для продолжения. Вопросы и ревью пропускают вперёд независимые фичи. Ошибка инфраструктуры или проверки останавливает текущий проход. Чтобы продолжить после ответа или окончания прохода, запустите очередь снова.
- **Решения.** На вкладке «Требуют решения» находятся вопросы и ревью. Ответ остаётся в карточке. «Отложить» убирает вопрос в отдельный список. Сводки, ссылки на снимки PNG/JPEG/WebP/GIF и видео MP4/WebM доступны внутри карточки. Диспетчер печатает изменения статусов по F-ID. Агенту передаются бриф текущей фичи, решения и ссылки на нужные документы.
- **Контекст.** Каждая фича начинается в свежей CLI-сессии. Внутри большой фичи исполнитель обновляет локальную сводку и возвращает handoff с ближайшим шагом. Диспетчер открывает новую сессию в той же рабочей копии. При ошибке переполнения он использует сохранённую сводку или состояние Git. Лимит — четыре попытки за проход одной фичи. После него нужна проверка карточки. Решение о ранней передаче принимает исполнитель; точное число оставшихся токенов диспетчер не измеряет.
- **Коммит.** Исполнитель перечисляет изменённые файлы. Диспетчер проверяет список, запускает команду приёмки и создаёт один коммит с F-ID и названием изменения. В тот же коммит входит отметка verified в Feature Index. После проверки диспетчер делает fast-forward выбранной локальной ветки и push конкретного SHA в одноимённую удалённую ветку. Если ветка продвинулась, диспетчер повторяет проверку после rebase. При ошибке отправки откройте карточку и нажмите «Повторить push». До успешной отправки очередь ждёт. Перед сменой назначения завершите очередь и закройте доску, затем выберите новую ветку в конструкторе и заново запустите доску.
- **Следующий этап.** После принятия очереди запустите обычный `scripts/run-pipeline.cjs` для сборки. Он сверит карточки с индексом и коммитами и передаст результат к итоговому QA.

## Хранение и восстановление

Карточки и решения хранятся в отдельной папке назначения внутри `.git/gfk-robocop/`. Запись атомарная. Рабочие копии остаются в системной временной папке по путям из карточек. Снимки и видео для постоянного хранения включайте в файлы фичи или сохраняйте отдельно перед очисткой временных файлов. Не удаляйте рабочие копии во время работы и ревью.

После перезапуска используйте ту же команду. Новые F-ID добавляются из индекса выбранной ветки. Бриф существующей карточки редактируйте через доску. Для пересмотра существующих строк или смены платформы закончите активные задачи, закройте доску, архивируйте каталог состояния и затем начните новую очередь. Для переключения между ручным режимом и Робокопом достаточно закрыть доску и открыть её с обновлённым JSON.

После аварии проверьте PID из `owner.lock` и завершение связанных Codex-процессов. Удалите оставшийся lock только после их остановки. Прерванная задача сохраняет рабочую копию и появится в списке решений. Восьмичасовой запуск, доступ к модели, редакторам и их реальные проверки зависят от среды конкретного проекта.
