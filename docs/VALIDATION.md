- `python scripts/kit.py validate`: PASS, сохранены 45 навыков и 7 профилей.
- `python -m unittest discover -s tests -v`: 22 теста, 20 PASS, 2 SKIP (прежние symlink-проверки требуют привилегий Windows).
- Проверены вложенные изображения, кириллические пути/пробелы, экранирование текста, отказ от опасных URL, отсутствующих/слишком больших файлов и неявной перезаписи HTML.
- Реальный профиль core установлен во временный каталог; его скопированный помощник собрал доску из скопированных примеров без обращения к исходной папке.

На ширине 390 px горизонтального переполнения нет. Для browser-tool проверки использован временный localhost-сервер; помощник сам сервер не запускает.
- Новый игровой проект и полный игровой процесс в этой проверке не запускались. Будущее автоматическое срабатывание интервью не подтверждается unit-тестами; опубликованные ниже прежние поведенческие прогоны относятся к состоянию от 26 октября.

## Исходная проверка версии

Дата: 26 октября 2026. Локальная среда: Windows, PowerShell, Python 3.14. Набор требует Python 3.10+ и использует стандартную библиотеку. GitHub Actions дополнительно запускает проверку структуры и тесты на Windows/Python 3.14, Ubuntu/Python 3.10 и macOS/Python 3.12; актуальный результат доступен во вкладке Actions репозитория.

## Структура и инструкции

- `python scripts/kit.py validate`: PASS, 45 skill roots, 7 профилей; manifest/name/description/профили и проверка персональных путей новых навыков.
- Системный `skill-creator/scripts/quick_validate.py`: все 45 PASS при запуске Python с `-X utf8`. Для этой внешней проверки PyYAML 6.0.3 установлен только во временный каталог; runtime-установщик набора PyYAML не требует.
- Все 45 skill-папок имеют LICENSE/лицензионный файл. Для Playwright сохранён NOTICE; у Blender добавлен полный MIT notice из закреплённого upstream.
- Проверены относительные Markdown-ссылки внутри репозитория. Устанавливаемые ресурсы ведущего навыка находятся в его собственной папке; роли разрешаются через установленную коллекцию.
- В `skills/` нет персональных абсолютных путей к компьютеру пользователя. У upstream Unity есть демонстрационный `/Users/dev/MyProject` внутри JSON-примеров, он не является настройкой установки.

## CLI и перенос

Unit suite: `python -m unittest discover -s tests -v` — 15 тестов, 13 PASS, 2 SKIP. Проверены:

- одинаковая повторная установка без изменений;
- полный preflight конфликта до записи, dry-run без создания папки;
- явная замена с сохранением оригинала и rollback при смоделированном сбое;
- сохранение существующих документов при init;
- корректный JSON при Unicode/кавычках/переносах строки в имени проекта;
- невалидный JSON-шаблон до записи файлов;
- безопасный вывод JSON в CLI при старой кодировке Windows cp1251;
- отказ от `..` в manifest/path, неверные name/profile;
- allowlist ZIP, исключение .git/.env/cache/private/local-extras и воспроизводимость архива;
- настоящий Windows junction: отказ без обхода ссылки.

Два symlink-теста пропущены, потому что текущая Windows-сессия не имеет привилегии создавать symlink (WinError 1314). Это не PASS этих сценариев. Проверка junction выполнена отдельно и прошла.

Интеграционный прогон с настоящим набором во временных папках: полная установка 45 → повторно все unchanged → init создаёт 8 документов и валидный state.json → ZIP → распаковка в другой путь с пробелами → validate → установка Web-профиля 19. Конфликты/исходная коллекция пользователя не затрагивались.

Упаковщик использует allowlist файлов корня и каталогов; он не является универсальным сканером секретов внутри разрешённых каталогов. В поставляемые каталоги не следует добавлять ключи/личные выгрузки. Архив не содержит .git history, поэтому его SHA256 фиксируется в выводе `package`, а локальная Git-история остаётся в исходной папке.

## Поведенческая проверка

Независимый агент прочитал навыки и выполнил два сценария без записи игровых файлов и сетевых действий:

1. Пустая идея + «я хочу создать игру»: первый ответ содержит только вопрос об идее, без стандартной анкеты и bootstrap.
2. Уже заданы 3D, дроны, телефон, Web MVP, free, существующий Unity и запрос только на концепт/Feature Index: известные решения не спрашиваются повторно, уточняется пилотирование vs управление маршрутами, Unity и сборка не запускаются.

По проверке добавлена явная граница requested outcome: concept/index-only не требует technical-plan или установки стека. Это tabletop-проверка маршрутизации, не реальная разработка игры и не гарантия поведения любой модели.

Независимый review также обнаружил и исправил прямой запуск .sh без executable bit в ZIP и противоречивое обязательное предложение глобального npm install. Примеры Playwright теперь вызывают `bash "$PWCLI"`; Windows может использовать прямой npx путь.

## Что ещё не проверено

В рамках сборки инструмента не создавалась конкретная игра от идеи до runtime. Не выполнялись реальные market queries под игровую идею, человеческий плейтест, запуск Unity/Roblox/Blender, генерация изображений/аудио, mobile native build и публикация в магазинах. Они проверяются в выбранном игровом проекте при наличии нужных программ/доступов.

Наличие минимального plugin.json не означает, что плагин прошёл проверку каталога. Проверенный путь установки — CLI из клона Git или распакованного ZIP. Исходная папка пользовательских навыков сохранена без изменений.
