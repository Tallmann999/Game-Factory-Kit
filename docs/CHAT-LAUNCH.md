# Запуск чатов из конструктора

**Работать в чате Codex** готовит обычный чат в папке игры. Отправьте сообщение один раз; работа и итог появятся в этом же чате. Если браузер блокирует `codex://`, в карточке раскройте «Если браузер не открыл Codex», скопируйте задание в новый чат нужного проекта. Браузер не сообщает конструктору, отправлено ли сообщение; статус меняется после команды `begin` из чата.

**Запустить автоматически** запускает локальный Codex CLI. Ход выполнения виден в карточке, ID/ссылка доступны после `thread.started`. Раннее открытие CLI-чата в Desktop может показать неполную историю. Поэтому автоматическое открытие окна происходит после завершения. Успех передачи ссылки ОС не подтверждает видимость окна; при ошибке остаются ID, журнал и инструкция. Это отдельно от результата задания.

На Windows откройте обычный PowerShell пользователя:

```powershell
./scripts/start-project.ps1 -Project "D:\Games\MyGame"
```

Для фиксированного адреса добавьте `-Port 8304`, для конкретного CLI — `-CodexPath "C:\path\codex.exe"` или абсолютный путь к `codex.js`. При прямом запуске Node используется `GFK_CODEX_PATH`. Без настройки сохраняется поиск CLI в PATH; фактически выбранные путь и версия показаны в «Среде запуска Codex».

Из среды агента сервер запускается через разрешённый механизм обычной учётной записи. Нельзя отключать глобальный sandbox, подменять пользователя или стирать защитные переменные среды. Если такого механизма нет, дайте автору команду выше; ручной чат остаётся доступным. Не выдавайте открывшуюся страницу за проверку автоматического выполнения.

Перед автозапуском проверяются пользователь, доступность профиля, версия выбранного CLI и `login status`. Сеть и ответ модели проверяются уже при выполнении. При `CodexSandbox*` или `CODEX_SANDBOX_NETWORK_DISABLED=1` автозапуск не создаёт исполнителя. Настройте вход командой выбранного CLI `login` в обычной оболочке; ключи в конструктор не вводятся.

Карточка показывает время последнего события и состояние связи. Heartbeat процесса не считается прогрессом модели. После 3 минут без событий появляется «Давно нет новых событий». Лимит одного шага по умолчанию — 30 минут. До запуска сервера можно настроить `GFK_STAGE_STALL_SECONDS` (5–3600) и `GFK_STAGE_TIMEOUT_SECONDS` (30–28800). Это лимиты шага, не восьмичасовой очереди Робокопа.

**Остановить задание** проверяет PID и время создания worker/CLI, завершает только их дерево и разрешает новый запуск после подтверждённой остановки. Исходники и частичные документы сохраняются. Поздний ответ отменённой попытки не меняет карточку или новую попытку. Для старых запусков без сохранённого времени процесса требуется отдельная сверка дерева и владельца; удаление job JSON у живого worker запрещено.

Журнал находится в `.game-factory/stage-runs/<run-id>.events.jsonl`, содержит последние события и очищенные сообщения, максимум около 128 КБ. Сырые аргументы команд и результаты инструментов туда не записываются. Ошибки CLI также видны в карточке. Состояние и журнал остаются локально в игре.

Проверка перед выдачей инструмента: preflight → одно минимальное задание → ID и прогресс → результат в той же карточке; отдельно проверьте зависший процесс, отмену и переход в ручной режим. Факт открытия окна проверяется пользователем/доступным UI отдельно от запуска CLI.
